  Research §11 notes the spec does not define this. Recommended: envelope with `items`/`total`/`page`/`pageSize` — it carries pagination metadata and is unambiguous when `total` is 0.  
  Files affected: none yet (applied in Phase 4).

  Decide whether the `roles` array in list responses (`GET /api/movies`) includes all categories or cast-only (`actor`/`actress`).  
  Research §10 recommendation: cast-only in list (smaller payloads), full roles in detail.  
  Files affected: none yet.  
  **Exit criteria:** decision recorded in this file.

## Phase 2 — Store Package

- [ ] **T2 — Implement `internal/store` loader**  
  Files: `internal/store/store.go` *(new)*  
  - `Load(dataDir string) (*Store, error)`: reads `movies.json`, `actors.json`, `ratings.json`; returns error on missing or malformed file.  
  - Pre-joins ratings into movies by `movieId` (1:1, 100 records each); log a warning and continue if any rating is absent — do not panic.  
  - Internal indexes: `moviesByID map[string]*enrichedMovie`, `actorsByID map[string]*Actor`.  
  - Genre list: all distinct values from `genres` arrays across all movies, sorted alphabetically; computed once at load time.  
  - `Store` is immutable after `Load` returns — no exported setters, no pointer aliasing of internal slices.  
  **Exit criteria:** `go build ./...` passes; loading the real dataset in `src/data/` produces no errors and no panics; store struct has no exported mutable fields.

- [ ] **T3 — Unit tests for store**  
  Files: `internal/store/store_test.go` *(new)*, `internal/store/testdata/` *(new — 3 movies, 3 actors, 3 ratings)*  
  Fixture must cover: actor with `deathYear: 0`, actor with `birthYear: 0`, movie with `"self"` role category, missing `characters` field on a director role, genres that would deduplicate.  
  Table-driven cases:  
  - Happy-path load: movie count, actor count, genre list, rating join  
  - Missing `ratings.json`: error returned  
  - Malformed JSON in any file: error returned  
  - Ratings-movie join: `rating` and `votes` appear on the correct movie  
  - Genre deduplication: genre appearing in two movies counted once, sorted  
  **Exit criteria:** all store tests pass; at least two error-path cases covered.

## Phase 4 — Endpoint Handlers

- [ ] **T5 — `GET /api/genres`**  
  Files: `internal/server/genres.go` *(new)*  
  Returns the pre-computed sorted genre slice from the store.  
  **Exit criteria:** `curl /api/genres` → `["Action","Adventure",...]`; status 200; JSON array, not object.

- [ ] **T6 — `GET /api/movies`**  
  Files: `internal/server/movies.go` *(new)*  
  - Parse and validate all query params: `q`, `genre`, `year`, `rating`, `actorId`, `pageNumber`, `pageSize`.  
  - Apply filters as AND (research §7): `q` → case-insensitive substring on `title`; `genre` → case-insensitive exact match in `genres` array; `year` → exact integer match; `rating` → joined rating ≥ value; `actorId` → any `roles[].actorId` equals value (all categories).  
  - Sort: rating desc, title asc (research §8.1).  
  - Paginate after sort.  
  - Return D1 envelope; `items` uses `MovieListItem` shape (D2-determined role scope).  
  - Empty result: `{ "items": [], "total": 0, "page": 1, "pageSize": 20 }` — never 404.  
  **Exit criteria:** all filter combinations produce correct subsets on the real dataset; empty result returns 200 not 404; invalid params return 400 with `{ "error": "..." }`.

- [ ] **T7 — `GET /api/movies/{id}`**  
  Files: `internal/server/movies.go` *(modify)*  
  - Extract path param; validate format `^tt\d{5,9}$` — 400 on mismatch.  
  - Lookup in store; 404 with `{ "error": "not found" }` on miss.  
  - Response uses `MovieDetail` shape: full `roles` array (all categories), embedded `rating` and `votes`.  
  **Exit criteria:** known ID → 200 with full roles and rating; unknown valid ID → 404; malformed ID → 400.

- [ ] **T8 — `GET /api/actors`**  
  Files: `internal/server/actors.go` *(new)*  
  - Parse and validate: `q`, `pageNumber`, `pageSize`.  
  - Filter: `q` → case-insensitive substring on `name` (when present).  
  - Sort: name ascending (research §8.2).  
  - Paginate after sort.  
  **Exit criteria:** `?q=wood` returns Elijah Wood; no filter returns all actors; pagination math is correct for the 553-record set.

- [ ] **T9 — `GET /api/actors/{id}`**  
  Files: `internal/server/actors.go` *(modify)*  
  - Validate format `^nm\d{5,9}$` — 400 on mismatch.  
  - Lookup in store; 404 on miss.  
  - Response includes `movies` array from actors.json (denormalized; no rating join required here).  
  **Exit criteria:** known ID → 200 with movies list; unknown valid ID → 404; malformed ID → 400.

## Phase 5 — Input Validation

- [ ] **T10 — Validation helpers**  
  Files: `internal/validate/validate.go` *(new)*  
  Implement one function per rule; each returns `(value, error)`:  

  | Param | Type | Rule |
  |---|---|---|
  | `pageNumber` | int | [1, 10000], default 1 |
  | `pageSize` | int | [1, 1000], default 20 |
  | `q` | string | length [2, 20] when present |
  | `year` | int | [1888, 2100] when present |
  | `rating` | float64 | [1.0, 10.0] when present |
  | `actorId` | string | `^nm\d{5,9}$` when present |
  | movieId (path) | string | `^tt\d{5,9}$` |

  Error value must carry a human-readable message that handlers can write directly into `{ "error": "..." }`.  
  No panic on empty string or absent param.  
  **Exit criteria:** `go build ./...` passes; no exported state; no dependency on `net/http`.

- [ ] **T11 — Unit tests for validation**  
  Files: `internal/validate/validate_test.go` *(new)*  
  Table-driven; every rule must cover: valid value, lower boundary, lower boundary − 1, upper boundary, upper boundary + 1, non-numeric/non-matching string, empty string (absent param).  
  **Exit criteria:** all boundary conditions tested; 0 failures.
