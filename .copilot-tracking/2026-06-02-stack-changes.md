## Key Decisions Made During Implementation

1. **Go version in `go.mod`**: Local Homebrew installed Go 1.26.3, which wrote `go 1.26.3` to `go.mod`. Lowered to `go 1.22` to match the `golang:1.22-bookworm` Docker builder image.

2. **`runAsUser: 65532` in Deployment**: The distroless image uses the named user `nonroot`, which Kubernetes' `runAsNonRoot` check can't verify without a numeric UID. Added `runAsUser: 65532` (distroless's nonroot UID) to the pod securityContext.

3. **Cluster access via `docker exec`**: The k3d `movies` cluster load balancer (which exposes the API on host port 59267) failed to start because host port 3000 was occupied by a Next.js dev server. All `kubectl` operations were run via `docker exec k3d-movies-server-0 kubectl` to avoid disrupting the dev server. Image import used `k3d image import` (which doesn't require the lb).

4. **Version hardcoded as constant**: Plan allowed either `-ldflags` injection or hardcoded constant for Session 1. Used a package-level `var version = "0.1.0"` so it can be overridden by ldflags in future builds.

5. **Go installed via Homebrew**: Go was not present on the host; installed via `brew install go` (1.26.3).
