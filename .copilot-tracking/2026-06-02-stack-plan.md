### 2. Config package

- [x] Create `internal/config/config.go` — reads three env vars with defaults:
  - `MOVIES_PORT` → default `8080`
  - `MOVIES_LOG_LEVEL` → default `info`
  - `MOVIES_DATA_DIR` → default `/data`

### 3. Server package — `/version` and `/healthz`

- [x] Create `internal/server/server.go` — registers both routes on a `*http.ServeMux`; version string injected via constructor (not hard-coded)
- [x] `GET /version` — responds with plaintext semver (e.g. `0.1.0`), `Content-Type: text/plain`, no trailing whitespace or newline beyond the body terminator; handler must not block on any data-loading goroutine
- [x] `GET /healthz` — responds `200 OK`, body exactly `pass`, `Content-Type: text/plain`; always succeeds regardless of data state
- [x] Create `internal/server/server_test.go` — `httptest.NewRecorder` tests for both routes: status code, exact body, content-type
- **File targets:** `internal/server/server.go`, `internal/server/server_test.go`
- **Exit criteria:** `go test ./internal/server/...` passes; both body assertions check for exact string (no trailing space/newline)

---

### 4. Wire up `main.go`

- [x] Create `cmd/moviesx/main.go` — loads config, constructs server, calls `http.ListenAndServe`; version injected via `go build -ldflags "-X main.version=0.1.0"` (or hardcoded constant for session 1)
- [x] Structured log line on startup: `{"level":"info","msg":"listening","port":"8080"}`
- **File targets:** `cmd/moviesx/main.go`
- **Exit criteria:** `go run ./cmd/moviesx` starts without error; `curl -s localhost:8080/healthz` returns `pass`; `curl -s localhost:8080/version` returns `0.1.0`; Ctrl-C exits cleanly

---

### 5. Multi-stage Dockerfile

- [x] Stage 1 (`builder`): `golang:1.22-bookworm`, copies source, runs `CGO_ENABLED=0 GOOS=linux go build -ldflags "-s -w" -o /moviesx ./cmd/moviesx`
- [x] Stage 2 (`final`): `gcr.io/distroless/static-debian12:nonroot` — copies binary only; `USER nonroot:nonroot`; `EXPOSE 8080`; `ENTRYPOINT ["/moviesx"]`
- [x] Create `.dockerignore` — excludes `.git`, `.copilot-tracking`, `*.md`, test files
- **File targets:** `Dockerfile`, `.dockerignore`
- **Exit criteria:** `docker build -t moviesx:dev .` exits 0; `docker inspect moviesx:dev --format '{{.Config.User}}'` shows `nonroot:nonroot`; `docker run --rm -p 8080:8080 moviesx:dev` starts and `curl localhost:8080/healthz` returns `pass`; image size < 20 MB (`docker image inspect moviesx:dev | jq '.[0].Size'`)

---

### 6. Kubernetes manifests

- [x] Create `k8s/deployment.yaml`:
  - `replicas: 1`
  - Container image: `moviesx:dev` with `imagePullPolicy: Never` (local k3s)
  - Env vars: `MOVIES_PORT=8080`, `MOVIES_LOG_LEVEL=info`, `MOVIES_DATA_DIR=/data`
  - `securityContext.runAsNonRoot: true`
  - `containerPort: 8080`
  - Liveness probe: `GET /healthz`, `initialDelaySeconds: 2`
  - Readiness probe: `GET /healthz`, `initialDelaySeconds: 2`
- [x] Create `k8s/service.yaml`:
  - `type: ClusterIP`
  - `port: 80 → targetPort: 8080`
- **File targets:** `k8s/deployment.yaml`, `k8s/service.yaml`
- **Exit criteria:** `kubectl apply --dry-run=client -f k8s/` exits 0 with no warnings; manifests are valid YAML and reference correct label selectors

---

### 7. Load image into k3s and deploy

- [x] Build image: `docker build -t moviesx:dev .`
- [x] Import into k3s containerd: `docker save moviesx:dev | sudo k3s ctr images import -`
- [x] Apply manifests: `kubectl apply -f k8s/`
- [x] Wait for rollout: `kubectl rollout status deployment/moviesx`
- **File targets:** none (operational steps)
- **Exit criteria:** `kubectl get pods` shows pod in `Running` state and `READY 1/1`

---

### 8. End-to-end verification

- [x] Port-forward: `kubectl port-forward svc/moviesx 8080:80`
- [x] `curl -s localhost:8080/healthz` → body is exactly `pass`, HTTP 200
- [x] `curl -s localhost:8080/version` → body is exactly `0.1.0` (no trailing whitespace), HTTP 200
- **File targets:** none (verification steps)
- **Exit criteria:** Both assertions pass in the terminal; session can be considered complete

## Parking Lot (deferred to later sessions)

| Item | Reason deferred |
|---|---|
| CLI flags for config | Env-only is sufficient for k8s; flags add surface area without value now |
| `GET /metrics` (Prometheus) | Session 1 baseline only; Prometheus stack not yet deployed |
| OpenAPI 3 spec + Swagger UI | Requires defining data-model types first; no routes beyond /version and /healthz yet |
| Data loading from `MOVIES_DATA_DIR` | No data format decided; directory is wired in config but not read |
| Helm chart | Manifests sufficient for local k3s; Helm adds overhead before schema is stable |
| Resource requests/limits in Deployment | Safe default for dev; tune after profiling under real load |
| ConfigMap / Secret for env vars | Plain env in Deployment is fine for local k3s; extract when secrets appear |
| Ingress / LoadBalancer | Port-forward is sufficient for local verification |
| `HorizontalPodAutoscaler` | Single replica + no load; premature |
| RBAC / NetworkPolicy | Not needed until multi-namespace or multi-tenant scenario |
| CI/CD pipeline | Out of scope until core API shape is stable |
| Graceful shutdown (SIGTERM handler) | Distroless + k8s rolling update works without it for single replica; add in Session 2 |
| Multi-arch image build (`arm64`/`amd64`) | Add when targeting a remote registry; local k3s matches host arch |
